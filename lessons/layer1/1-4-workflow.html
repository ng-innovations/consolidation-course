Layer 1 — Lesson 4

The consolidation workflow

Consolidation is a pipeline. Data comes in from many sources, passes through a fixed sequence of steps, and emerges as a single set of group financial statements. Every step has a purpose; nothing is optional; the order matters.

This lesson gives you the bird's-eye view. Each step gets its own dedicated lesson in Layer 2. For now, the goal is to understand the shape of the whole process and why the steps appear in the order they do.

The four phases

At the highest level, consolidation has four phases. Inside each phase are several specific steps.

Phase A: Setup

Setup is the work that doesn't change every period. It's the configuration of the consolidation engine — the rules, the structure, the policies. You do most of it once when first standing up consolidation for a group, and then update it as the group changes (new subsidiary, new account, new policy).

Three families of setup:

  • Standards & policy. What's the reporting currency? When does the fiscal year end? Which FX rates apply to which account types? What's the materiality threshold for intercompany mismatches? These are global rules.
  • Entity setup. The group hierarchy and the ownership percentages between entities. Which entities use which consolidation method (full, equity, etc.).
  • Account setup. The group chart of accounts, the mapping from each subsidiary's local accounts to group accounts, which accounts are flagged as intercompany, which FX rate type applies to which account.

Phase B: Ingest

Each period (typically each month), every subsidiary has to submit its trial balance to the corporate consolidation team. The Ingest phase is about getting that data into the system and verifying it's usable.

  • Collect. Pull or receive each subsidiary's trial balance — sometimes from an integration with their accounting system, sometimes as a manual file upload.
  • Validate & normalize. Check that the data is well-formed (numeric, valid currency codes, required fields present). Apply the mappings so local accounts become group accounts, local entities become group entity codes, etc. Verify that each subsidiary's trial balance actually balances (total debits equal total credits). Confirm every expected subsidiary has submitted.

By the end of Ingest, the system has clean, validated, mapped Local data from every subsidiary — still in each one's functional currency, but ready to be processed.

Phase C: Consolidate

This is the heart of the process — the transformations that turn standalone subsidiary data into group data. The order matters because each step depends on the previous one.

  • Carryforward validation. For balance sheet accounts, this period's opening balance must equal last period's closing balance. The system verifies and rolls these forward.
  • Currency translation. Each foreign subsidiary's numbers are translated from its functional currency to the group's presentation currency. The balancing item is CTA.
  • Standardize. Apply group accounting policies. Calculate goodwill for any acquisitions. Post any pre-elimination topside entries.
  • Intercompany elimination. Match intercompany balances between group entities and remove them. AR with AP. Intercompany revenue with intercompany expense.
  • Investment elimination & NCI. Eliminate the parent's investment account against the subsidiary's equity. Calculate the non-controlling interest share. Allocate net income between parent and NCI.
  • Group adjustments. Final post-ownership topside entries — reclassifications, presentation adjustments, anything that needs to happen at the group level after all the math is done.

Phase D: Close

The consolidated numbers exist. Now produce the output, lock it down, and prepare for next period.

  • Reporting. Generate the consolidated balance sheet, income statement, cash flow statement, equity rollforward, and any supplementary reports (intercompany matrix, flux analysis, etc.).
  • Lock & snapshot. Once final reports are approved, lock the period to prevent further changes and take a snapshot for audit purposes.
  • Carryforward to next period. Roll closing balances into next period's opening balances so the cycle can begin again.

What flows through the pipeline

At each step, the data is in a particular state. The data transformations from raw subsidiary submissions to final consolidated reports happen through a series of well-defined intermediate states. We'll cover these in detail in Lesson 1.7, but here's the preview:

Local → Translated → Standardized → Eliminated → Ownership-Adjusted → Top

Each transition is a phase of the pipeline. Each state has a clear definition. Devs working on the system will see and operate on data in each of these states.

Why the order matters

You might wonder: can't some of these steps run in parallel, or in a different order?

Mostly no. Each step builds on the previous one:

  • You can't translate currency before you've validated the underlying balance — translating bad data just produces bad data faster.
  • You can't eliminate intercompany balances before currency translation — because they're in different currencies until then.
  • You can't calculate NCI before eliminations — because the subsidiary's equity (which NCI is a share of) isn't right until elimination cleanup is done.
  • You can't report numbers that haven't been adjusted, eliminated, and allocated.

That's why consolidation is a pipeline, not a bag of independent calculations.

Why this matters for the software

For developers

The application enforces this pipeline. Steps run in order. Each step's output becomes the next step's input. Devs working on a particular step need to know exactly what state the data is in when their code starts, and what state it needs to leave the data in when it finishes.

This is also why the system has to support re-running the pipeline. If someone discovers a mapping error after running through to step 9, the fix has to flow forward through every subsequent step. Idempotent, deterministic, replayable steps make this possible.

Summary

  • Consolidation has four phases: Setup, Ingest, Consolidate, Close.
  • Setup is mostly one-time configuration; the other three run every period.
  • Inside Consolidate, the steps are: carryforward, FX translation, standardize, IC elimination, investment elimination & NCI, group adjustments.
  • The order matters — each step depends on the previous one.
  • Data passes through well-defined intermediate states between steps.
